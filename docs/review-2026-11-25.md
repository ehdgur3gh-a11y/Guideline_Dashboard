# 배포 전 검토 기록 (2026-11-25)

웹 디자이너·현업 설계 실무자 입장에서 10개 항목으로 나눠 검토했다. 원문 HWP와 화면 데이터를 대조하고, 데스크톱(1440)·태블릿(768)·모바일(375) 화면을 직접 확인했으며, 1,280개 절 전부를 화면에 그려 오류·넘침을 기계적으로 검사했다. 바로 고칠 수 있는 것은 고쳤고, 판단이나 자료가 필요한 것은 맨 아래 **남은 일**에 적었다.

## 항목별로 고친 것

### R1 내용 정확성 (원문 대조)
- 표 셀 안 글상자·그림 속 글이 빠지던 것 복구.
- 제5편 원문 목차의 번호 오기(10.2.1을 1.2.1로 표기)를 제목으로 맞춰 찾도록 함.
- 제4편 본문 뒤 **참고문헌·부록(설계 사례)** 이 마지막 절에 붙어 있던 것을 따로 묶음(`4-ref`, `4-app-…`).
- 장 간지(표지) 쪽이 장 제목으로 잡히던 것, 참고문헌 번호('32. 2011년도 …')를 절 번호로 오인하던 것 제외.
- **제3편 4.9.4 배수로** 절이 빠져 앞 절에 섞여 있던 것 복구(제목 문단에 표가 붙어 있던 경우).
- 제7편 2.8의 **각주**(KS A 0110 "제도-척도")가 빠지던 것 — 각주·미주를 본문 자리에 '(주: …)'로 넣음.
- 원문이 부등호 자리에 꺾쇠를 쓴 5곳('L〈 100m', 'Q〈30')을 '<'로 표시(뒤에 숫자가 올 때만).

### R2 수식·표
- 표 셀 안 수식도 그림(분수·첨자)으로 표시.
- 붙여 쓴 수식 명령('cdotH', 'cosalpha')이 글자 그대로 보이던 2건 수정.
- **KoPub 돋움의 '<' '>'가 '〈 〉' 모양이라 작은 글씨에서 '('로 읽힘** — 예: 표 4.2.1 'hw+he<1.5'가 'hw+he(1.5'처럼 보임. 이 두 글자만 시스템 글꼴로 표시.
- 표 '엑셀로 복사'·CSV에서 수식 셀이 HWP 수식 원문(`{D}_{15F} over {D}_{85B} ~<~ 5`)으로 나가던 것을 한 줄 글(`D15F/D85B < 5`)로. 검색 미리보기·AI 근거 표도 같은 글을 씀.
- 병합 셀 겹침·빈칸 없음 확인.

### R3 검색
- 전각 숫자('４.２.１'), 한 글자씩 띄운 질의('여 유 고'), 'CN값', 꺾쇠 기호가 든 질의 처리.
- 띄어 쓴 낱말을 붙인 구절('설계 홍수량' → '설계홍수량')에 가산, 질의 키워드를 많이 덮는 절을 위로, 참고문헌·부록은 본문 기준보다 아래로.
- 결과 수 단위가 탭은 '문단 1,231', 목록은 '383개 절'로 달라 헷갈리던 것을 **절** 기준으로 통일(편 필터 숫자도 절).
- 오른쪽 '검색어가 들어간 표'에 흔한 낱말('기준')만 맞는 표가 앞에 오던 것 — 드문 키워드를 많이 덮는 표부터, 흔한 낱말만 맞는 표는 제외('필댐 여유고 기준' 39개 → 7개).
- 이상한 입력 30종(빈칸, 스크립트 태그, 정규식 기호, 이모지, 500자 등) 예외 없음, 가장 느린 질의 8ms.

### R4 링크·이동
- 모든 절·표·업무 흐름·목차·앞뒤 절 링크 확인(깨진 링크 0). 시설 아이콘 12개의 장 연결 확인.

### R5–6 화면 (데스크톱·태블릿·모바일)
- 홈 시설 아이콘이 8개+4개로 한쪽이 비던 것을 **6×2**로(디자인 시안 Main 보드도 같이 고침).
- 태블릿에서 편 필터 7줄이 결과를 화면 밖으로 밀던 것을 한 줄 칩으로.
- 그림 자리 표시가 흐름도 조각마다 하나씩(최대 31개 연속) 나오고, 꺼져 있는 '원문 쪽 보기'를 안내하던 것 — 이어진 조각과 뒤따르는 '[그림 n] 제목'을 한 상자로 묶고(1,372개 → 690개), 도형 속 글은 '그림 속 글자 보기'로 접어 둠.
- 모바일에서 표 첫 열이 한 글자 폭으로 눌려 세로로 읽히던 것 — 셀 최소 폭, 낱말 중간에서 끊지 않기(`keep-all`), 넘치면 표만 가로 스크롤.
- 긴 수식이 화면 밖으로 나가던 절(모바일 23개, 데스크톱 5개) — 수식만 그 자리에서 가로 스크롤.
- 모바일 검색창 안내문이 잘리던 것('검색어 또는 절 번호'로 짧게), 아직 없는 '원문 쪽 보기' 단추는 모바일에서 숨김.
- 표 모음에서 검색어 강조가 줄 전체를 노랗게 채우던 것 수정.

### R7 접근성
- **'본문 바로가기'가 첫 화면으로 튕기던 버그**(해시 라우팅과 충돌) — 초점만 본문으로 옮기도록.
- 화면 전체(`#app`)가 `aria-live`라 화면이 바뀔 때마다 화면 읽기 프로그램이 페이지 전체를 읽던 것 제거 → 화면이 바뀌면 새 제목(h1)으로 초점 이동.
- 검색결과 화면에 h1이 없던 것 추가(화면에는 안 보임).
- 15px 미만 글자(태그·작은 글씨·하단 탭 13~14px)를 15px로.
- 주소에 깨진 % 표기가 있으면 화면이 멈추던 것 처리.

### R8–9 성능·보안·안정성
- 서버가 압축 없이, 캐시 확인(ETag)도 없이 매번 4.3MB를 보내던 것 — **gzip(0.95MB)**, 바뀌지 않았으면 304, HEAD 요청 본문 없음, 깨진 주소 400.
- 보안 헤더 추가: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Content-Security-Policy`. 화면 동작 영향 없음 확인.
- `web/` 밖 파일 접근 차단 재확인(`../`, `%2e%2e%2f`).
- 위 내용을 `tests/server.test.js`에 시험으로 넣음.

### R10 실무 작업 흐름
- 출처 복사: 부록 절에 '부록'이 빠져 본문 같은 번호와 헷갈리던 것('부록 1.1 사업의 목적'), 참고문헌 출처의 이중 공백 수정.
  예: `한국농어촌공사, 조사설계실무요령 제1편 농어촌용수(2018), 4.2.1 제당 규모 결정, [표 4.2.1] 제체의 비월류부 높이 기준, p.105~`
- 인쇄: 메뉴·목차·단추를 빼고, 끝에 **출처 줄**이 함께 찍히도록. 표는 행 중간에서 쪽이 나뉘지 않게.
- CSV: 엑셀 한글용 BOM, CRLF, 따옴표 처리 확인. 글자 크기(보통·크게·아주 크게)는 표까지 함께 커짐 확인.
- 실무 질의 20개 점검: '용수로 조도계수', '방조제 마루높이', '저수지 퇴사량', '도면 축척', '물받이 길이' 등 대부분 1~3위에 해당 절.

## 추가 작업: 위·아래첨자 (같은 날, 검토 3회)

원문 글자 모양(위첨자·아래첨자 속성)을 읽도록 추출기를 고쳤다. 위첨자 266곳, 아래첨자 599곳.

- 단위: `m3` → **m³**, `km2` → **km²** (152곳). 원문에서 서식 없이 그냥 `m3`로 쓴 28곳(품셈 '백호 0.7m3' 등)은 원문대로.
- 기호 첨자: 표 4.2.1 `Hf+hw+he` → H<sub>f</sub>+h<sub>w</sub>+h<sub>e</sub>, `D50` → D<sub>50</sub> 등.
- **공식의 지수**: 제1편 6.5.7 물받이 길이 `4.05H0.316 × q0.514 × D50-0.325`가 지수와 계수가 붙어 다른 수처럼 읽히던 것 → 4.05H<sup>0.316</sup> × q<sup>0.514</sup> × D<sub>50</sub><sup>-0.325</sup>. 이번 작업에서 가장 중요한 수정.
- 각도: 위첨자 `o`·`。`로 쓴 각도 2곳 → `12.5°`, `2.5°`.
- 원문이 표 칸 전체를 아래첨자로 둔 한글 구절('귀붙이기 한변의 길이')은 작게 그리지 않고 보통 글로.
- 검색은 `m3`·`m³`, `D50`·`D₅₀`을 같게 본다. 엑셀 복사·CSV는 `Hf+hw`, `H^(0.316)`처럼 한 줄 글로.

검토 1회차 — 데이터 전수 대조: 고치기 전 데이터와 18,042개 블록을 비교해, 위첨자 글자 바뀜과 각도 2곳 말고는 **달라진 글이 없음**. 원문 문단 대조 누락 19개로 그대로. 첨자 앞뒤 빈칸이 첨자 안에 들어가던 것(`av` + 빈칸 26개) 발견해 고침.
검토 2회차 — 화면: 데스크톱·태블릿·모바일에서 1,429개 화면(절 전체 + 수식·첨자가 든 표 뷰어) 오류·넘침·깨진 표시 0. 첨자가 있는 줄만 4px 벌어지던 줄 간격 발견해 고침(본문·표 뷰어).
검토 3회차 — 회귀: 전체 다시 만들기 후 시험 6종 통과, 검색 평가 변화 없음(1위 87%·5위 안 96%). `tests/data.test.js` 추가(첨자·각도·각주·되살린 절). AI 답변 검증의 수치 비교도 첨자 숫자를 보통 숫자로 보게 함(지금은 꺼져 있음).

## 추가 작업 2: 동의어 사전 보강 (같은 날, 검토 3회)

사전을 5묶음 → 41묶음으로 늘리고, 여러 낱말 표현 규칙(`PHRASES`: '펌프 용량' → 양수량, '콘크리트 치기' → 타설)을 더했다.

- 근거: 원문 괄호 표기('속도랑(암거)', '수준점(B.M)', '간접공사비(제경비)', '회전차(임펠러)', '사면보호사석(피복사석)'), 표준 용어 변경(법면→비탈면, 성토→흙쌓기), 현장에서 흔히 쓰는 말(집수면적, 에이프런, 캐비테이션, SPT, IRR). 후보마다 원문에 실제로 쓰였는지 세어 보고 넣었다.
- 넣지 않은 것: 수문↔게이트(수문=水文, 제5편), 제정(=制定), 굴착↔터파기(범위가 다름), **계획홍수량↔설계홍수량**(곳에 따라 구분해 씀 — 묶지 않기로 결정).
- 새 점검 `tests/eval_paraphrase.js`: 실무자 말과 원문 용어를 34쌍 짝지어, 원문 용어로 찾은 1위 절이 실무자 말로 찾아도 위에 오는지 본다(정답을 사람이 고르지 않음). **같은 1위 15% → 68%, 5위 안 35% → 94%**. 기존 평가 45문항도 떨어지지 않음(5위 안 96% → 98%).

검토 1회차 — 엉뚱한 일치: 띄어쓰기를 지우고 글자 그대로 찾기 때문에 짧은 말이 다른 낱말 속에 걸리는지 사전 낱말마다 실제 문맥을 뽑아 봤다. **기존 항목 '땅고르기=정지'가 '예정지'에 걸려 '땅고르기' 검색이 예정지조사 절까지 100개 넘게 끌어오던 것** 발견 → '정지공사·정지계획·정지고·정지토량·정지표고'로 바꿈(17개 절로 정리). 'n치'(조도계수 n치 2곳), 'bm'(수식 1곳), 'irr'(irrigation 1곳)은 한두 곳이라 그대로 둠.
검토 2회차 — 화면: '펌프 용량' 검색에서 동의어 표시가 사용자가 쓴 말('펌프용량')을 되풀이하던 것 → 원문 용어('양수량, 토출량')를 보이게. '펌프용량'을 붙여 쓰면 키워드가 둘로 겹치던 것 수정. 14개 질의 결과 화면·자동완성 확인, 오류 없음.

3. **폰·태블릿** — 원문 창(화면 전체)·크게 보기가 열린 채 폰의 '뒤로'를 누르면 절에서 나가 버리던 것 → **'뒤로'로 창만 닫힘**(✕로 닫으면 쌓인 기록을 거둬 다음 '뒤로'는 정상). 뒤로 가기 때 결과 목록 위치 복원도 그대로.
