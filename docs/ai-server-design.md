# AI 답변 서버 설계 (2단계)

작성: 2026-11-25 · 대상: 조사설계실무요령 대시보드 `#/ask` 화면

## 1. 목표와 원칙

실무자가 문장으로 질문하면 **조사설계실무요령 원문만 근거로** 답하고, 문장마다 근거 절(편·절·쪽)을 붙인다.

- 근거 없는 답은 만들지 않는다. 근거가 약하면 질문을 좁혀 달라고 되묻는다(시안의 '질문 좁히기' 화면).
- 답변은 참고용이며, 화면에 항상 원문 확인 안내를 붙인다.
- **모델은 갈아 끼울 수 있게** 만든다. 처음엔 사내 서버에서 돌리는 자체 모델을 기본으로 하고, 필요하면 외부 API(예: Claude)로 바꿀 수 있게 어댑터를 둔다.

## 2. 전체 구조

```
[브라우저: web/ 정적 화면]
        │  POST /api/ask  (질문)
        ▼
[답변 서버 (사내망, Node.js)]
  ① 근거 검색 ── data/*.json 을 메모리에 올려 BM25 + 제목 가중치 (+선택: 임베딩)
  ② 근거 묶음 구성 ── 상위 절 5곳의 해당 문단 ±1, 표 제목·셀
  ③ 답변 생성 ── 모델 어댑터 ──┬─ 자체 모델 (사내 GPU 서버, OpenAI 호환 API: vLLM / Ollama 등)
                               └─ 외부 API (선택: Claude API)
  ④ 인용 검증 ── 답변의 [n] 번호가 실제 근거를 가리키는지, 숫자·식이 근거에 있는지 확인
        │  SSE 스트림 (단계 → 근거 → 답변 글자 → 인용 → 완료)
        ▼
[브라우저: 진행 단계 · 답변 · 오른쪽 근거 패널]
```

- 답변 서버는 상태가 없다(질문 기록은 9장 정책에 따름). 원문 데이터는 지금 쓰는 `data/*.json`을 그대로 읽는다.
- 검색 엔진은 지금 브라우저에서 쓰는 `web/js/search.js`를 서버에서도 재사용하고, 2a 단계에서 순위를 개선한다.

## 3. 근거 검색 (가장 먼저 고칠 부분)

### 측정 결과 (현재 1단계 검색 그대로)

| 질문 | 1위로 잡힌 절 | 판단 | 근거 묶음 크기* |
|---|---|---|---|
| 물넘이 게이트가 없는 필댐의 여유고는 어떻게 정해? | 1편 4.2.1 제당 규모 결정 | 맞음 | 4,887자 |
| 배수개선 사업에서 침수분석은 어떤 순서로 해? | 2편 4.6.2 시행후 침수분석 및 시설규모 결정 | 맞음 | 2,641자 |
| 단가표 작성 시 노임 단가 기준은? | 6편 4.2.2 토공 | 애매 | 7,713자 |
| 방조제 둑마루 표고는 어떻게 결정해? | 4편 4.5.2 설계파고 | 애매(4.5 둑마루 표고 결정이 더 맞음) | 4,664자 |
| 양수장 펌프 용량은 어떻게 정하나요? | 1편 7.5.2 조절지의 종류 | 틀림 | 6,216자 |
| 저수지 설계홍수량 빈도는? | 7편 1.1.3 작성내용 | 틀림 | 8,836자 |

\* 상위 5개 절에서 검색어가 든 문단 6개씩과 앞뒤 1문단. 절 전체를 넣으면 15,000~128,000자로 커지므로 문단 단위로 잘라 넣는다.

**결론:** 근거 묶음은 질문당 약 3천~9천 자로 작다(작은 자체 모델의 문맥에도 들어감). 대신 **순위가 틀리면 어떤 모델도 맞게 답할 수 없으므로**, 모델보다 검색 개선이 먼저다.

### 개선안
1. **BM25 점수**: 흔한 낱말('없는', '정해')보다 드문 낱말('여유고', '둑마루')에 가중치.
2. **제목·경로 가중치**: 절 제목과 상위 장 제목(예: 제5장 양수장)에 든 낱말은 크게 반영.
3. **시설 사전**: '양수장 → 제1편 제5장', '방조제 → 제4편 제4장'처럼 시설명이 나오면 해당 장을 우선.
4. **(선택) 임베딩 검색**: 뜻이 같은 다른 표현까지 찾기. 사내에서 돌릴 수 있는 다국어 임베딩 모델(예: bge-m3 계열)을 쓰고, 1,280개 절의 문단을 미리 벡터로 만들어 둔다. 1~3으로 부족할 때만 추가한다.

### 2a 결과 (2026-11-25)

평가 세트 `tests/eval/questions.json`(초안 45문항, 실무자 검토 필요)으로 측정했다. 실행: `node tests/eval_search.js`

| 배포 전 검토 후 (부록·참고문헌 분리, 구절 가산, 덮은 키워드 비율, 수식 글 변환) | **87%** | **91%** | **96%** | **0.901** |

- 동의어·시설 사전은 `web/js/search.js` 맨 위 `SYNONYMS`, `FACILITY`에서 고친다. 고친 뒤에는 평가를 다시 돌려 점수가 떨어지지 않는지 확인한다.

## 4. 답변 생성 규칙 (모델 공통 프롬프트)

```
너는 한국농어촌공사 조사설계실무요령의 내용만으로 답하는 도우미다.
- 아래 [근거 1]~[근거 N] 안의 내용만 사용한다. 근거에 없는 수치·기준은 쓰지 않는다.
- 문장마다 근거 번호를 [1]처럼 붙인다.
- 근거가 질문에 답하기에 부족하면 답을 만들지 말고 "근거 부족"과 함께 되물을 질문 1개를 낸다.
- 근거끼리 같은 기호를 다른 뜻으로 쓰면(예: Hf) 그 사실을 알린다.
- 한국어로, 실무자가 바로 쓸 수 있게 간결하게 쓴다.
```

- 근거는 `[근거 n] 제1편 농어촌용수(2018) › 4.2.1 제당 규모 결정 · p.105~` 머리말 + 문단 원문으로 넣는다. 표는 제목과 셀을 탭으로 구분한 줄로 넣는다.
- **인용 검증(서버)**: 답변의 `[n]`이 1~N 범위인지, 답변에 나온 숫자(예: 2.0m, 0.5m)가 해당 근거 원문에 실제로 있는지 확인한다. 어긋나면 그 문장에 '근거 확인 필요' 표시를 붙이거나 답변을 다시 만든다.
- 외부 API를 쓸 경우 Claude의 인용 기능(근거를 문서·검색결과 블록으로 넣으면 인용 위치를 구조화해 돌려줌)을 쓸 수 있어 이 검증이 더 쉬워진다.

## 5. API 명세

### `POST /api/ask`
요청
```json
{ "q": "물넘이 게이트가 없는 필댐의 여유고는 어떻게 정해?", "vols": [1, 4] }
```
응답: `text/event-stream`
```
event: stage     data: {"step":"search","status":"done","found":5}
event: evidence  data: [{"n":1,"id":"1-4.2.1","path":"제1편 농어촌용수(2018) › 4.2.1 제당 규모 결정","page":105,"quote":"…허용여유고값…큰 값을 채택…"}, …]
event: stage     data: {"step":"answer","status":"running"}
event: delta     data: {"text":"필댐의 댐높이는 … 큰 값을 채택합니다."}
event: citation  data: {"sentence":0,"refs":[1]}
event: done      data: {"status":"answered" | "need_clarification" | "no_evidence", "clarify":"어떤 댐인가요?", "model":"local-…"}
event: error     data: {"code":"model_unavailable","message":"…"}
```
- 모델이 꺼져 있으면 `error`를 보내고, 화면은 지금처럼 **근거 후보만** 보여 준다(1단계 동작으로 자동 후퇴).

### `GET /api/health`
`{ "search": "ok", "model": "ok|down", "modelName": "…", "dataVersion": "2026-11-25" }`

## 6. 모델 선택지 비교

| 항목 | A. 자체 모델 (사내 GPU 서버) | B. 외부 API (예: Claude) |
|---|---|---|
| 비용 구조 | GPU 서버 구매·임대 + 전기·운영 인력. **질문당 비용 없음** | 서버 구매 없음. **질문마다 사용료** (7장) |
| 보안 | 질문과 원문이 사내망 밖으로 나가지 않음 | 질문과 근거 문단이 외부로 전송됨 → 공사 보안 검토 필요 |
| 답변 품질 | 모델 크기에 좌우. 작은 모델은 근거 밖 내용을 지어내거나 인용을 틀리는 경우가 더 많음 → 4장의 검증이 필수 | 한국어 기술문서 이해·인용 정확도가 높고, 인용 기능 내장 |
| 응답 속도 | GPU 사양과 동시 사용자 수에 좌우 | 대체로 빠름, 인터넷 연결 필요 |
| 운영 부담 | 모델 서버 설치·업데이트·장애 대응을 공사가 직접 | 키 관리와 사용량 관리 정도 |
| 라이선스 | 공개 모델마다 상업·기관 이용 조건이 다름 → 확인 필요 | 서비스 약관 |

## 7. 비용 비교 (추정)

**전제:** 질문 1건 = 근거 묶음 3~9천 자 + 지시문 → 입력 약 5천~1만 토큰, 답변 약 1천 토큰. 한국어 토큰 수는 실제 측정 전 추정치다.

외부 API 사용료 (Claude, 1건당, 입력 1만·출력 1천 토큰 기준)

| 모델 | 단가 (입력 / 출력, 100만 토큰당) | 1건당 | 월 2만 2천 건* |
|---|---|---|---|
| Claude Opus 5.5 | $4 / $20 | 약 $0.06 | 약 $1,320 |
| Claude Sonnet 5.5 | $2 / $10 | 약 $0.03 | 약 $660 |
| Claude Haiku 5.5 | $0.10 / $0.50 | 약 $0.0015 | 약 $33 |

\* 사용자 100명 × 하루 10건 × 22일 가정. 실제 사용량에 비례한다.

자체 모델
- 질문당 비용은 없지만, GPU 서버(구매 또는 임대), 전기, 설치·운영 인력이 고정으로 든다.
- 대략적인 규모: 7~8B급 모델은 GPU 1장(16~24GB)으로, 30B급은 48~80GB급 GPU가 필요하다. 동시 사용자가 많으면 더 필요하다.
- **사용량이 적으면 외부 API가, 많거나 외부 전송이 금지되면 자체 모델이 유리하다.** 정확한 손익분기는 공사의 GPU 조달 단가와 예상 사용량으로 계산해야 한다.

## 8. 자체 모델 구성안 (기본안)

- **서빙**: 사내 GPU 서버에 vLLM 또는 Ollama로 띄우고, 답변 서버는 OpenAI 호환 API로 호출 → 모델 교체가 설정 변경으로 끝난다.
- **모델 후보**: 한국어를 잘하는 공개 모델(예: LG AI연구원 EXAONE 계열, Qwen 계열 등) 중 2~3개를 9장 평가로 비교해 고른다. 각 모델의 이용 조건(라이선스)을 먼저 확인한다.
- **설정**: 답변 길이 상한 1,000토큰, 근거 밖 생성을 줄이도록 낮은 무작위성(temperature 0~0.2).
- **연결이 끊겼을 때**: 근거 후보만 보여 주는 1단계 화면으로 자동 후퇴.

## 9. 보안·운영
- **접근**: 사내망에서만 접속, 가능하면 사내 SSO로 로그인.
- **질문 기록**: 품질 개선용으로 질문·근거·답변·피드백(👍/신고)을 남길지, 남긴다면 보관 기간을 공사 정책으로 정한다. 개인정보는 남기지 않는다.
- **외부 API를 쓰는 경우**: 보안성 검토, 전송 데이터 범위(질문 + 근거 문단만, 파일·개인정보 없음)를 명시한다.

## 10. 품질 평가 (모델·검색 개선의 기준)
- **평가 질문 세트**: 실무자 실제 질문 30~50개 + 각 질문의 정답 절(예: '양수장 펌프 용량' → 제1편 제5장 해당 절)과 핵심 수치.
- **지표**:
  - 근거 적중률: 정답 절이 상위 5개 안에 드는가
  - 인용 정확도: [n]이 맞는 근거를 가리키는가
  - 수치 정확도
  - 근거 부족 질문에서 지어내지 않고 되묻는가
- 검색 개선(2a)과 모델 선택(2b)은 모두 이 세트로 비교한다.

## 11. 단계

| 단계 | 내용 | 산출물 |
|---|---|---|
| 2a | 검색 개선(BM25·제목·시설 사전) + 평가 질문 세트 | 근거 적중률 표, 개선된 `search.js` |
| 2b | 답변 서버 + 모델 어댑터 + 인용 검증, 화면 연결 | `server/`, `#/ask` 실답변 |
| 2c | 모델 2~3개 비교 평가 → 선정, 시범 운영 | 평가 보고서, 운영 가이드 |

### 진행 상황
- 2a 완료 (3장 '2a 결과').
- 2b 완료 (2026-11-25): `server/` — 근거 묶음, 공통 지시문, 모델 어댑터(OpenAI 호환 자체 모델 / 원문 발췌), 수치·근거 번호 검증, SSE API, 화면 연결. 가짜 모델로 종단 시험 통과. **실제 모델로는 아직 시험하지 않았다.**
- 다음(2c): 실제 자체 모델을 띄워 10장 평가 세트로 답변 품질 측정 → 모델 선정.

## 12. 결정이 필요한 것
1. 공사 보안 정책상 외부 AI API 사용이 가능한지 (불가하면 자체 모델로 확정)
2. 자체 모델용 GPU 서버 확보 방법(기존 장비, 구매, 사내 클라우드)과 예상 사용자 수
3. 질문 기록 보관 여부와 기간
