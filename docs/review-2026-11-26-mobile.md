# 검토 21차 — 실제 폰 브라우저에서 깨지는 곳 (2026-11-26)

크롬 계열 화면(360·375·390·780 가로)에서는 잘림·겹침·넘침이 잡히지 않음 → 브라우저마다 다른 기본 모양을 원인으로 보고 막음.
- 입력칸·선택칸·단추의 브라우저 기본 모양(아이폰 사파리의 회색 둥근 검색 상자·안쪽 그림자, 기본 화살표) 끄기(appearance: none). 선택칸(통합·시도·시군구·편)에는 직접 그린 화살표. 체크칸은 기본 모양 그대로(공사 청색).
- 아이패드 사파리가 16px보다 작은 칸을 누르면 확대하던 것: 검색 범위 선택칸 15px → 16px 이상.
- 삼성 인터넷·안드로이드 크롬의 강제 어둡게 보기로 색이 뒤집히던 것: color-scheme only light(meta·CSS).
- 누를 때 번쩍이는 파란 상자, 안드로이드 크롬 자동 글자 확대 끄기.
- 휴대폰 주소창·상태 표시줄 색: 홈은 청색 머리(#00285A), 나머지는 미색 — 미색 띠 아래 청색 머리가 붙어 끊겨 보이던 것.
- 옛 사파리(inset 모름)용 top/right/bottom/left.
- 표 주소가 틀릴 때 창 제목이 이전 표로 남던 것.
- 확인: 360px에서 10개 화면 넘침·잘림·겹침 0, 1440px 검색 화면 체크칸·선택칸 화살표 정상, 시험 통과.
- 남은 것: 폰을 가로로 눕히면(높이 360) 위 메뉴가 두 줄이라 첫 화면에 보이는 내용이 적음 — 깨지지는 않음.

## 22차 — 시설 카드 펼침 화살표 위치 (2026-11-27)
- 증상: 폰(375px)에서 시설 카드의 펼침 화살표가 주소 줄 글자('…1958년') 위에 겹쳐 떠 있었다. 화살표가 `position:absolute`라 위치가 글자 줄 높이에 따라 달라졌다.
- 고침: 카드 머리를 아이콘 | 내용 | 화살표 세 칸으로 나눠 화살표를 오른쪽 칸 세로 가운데에 둠. 펼친 상태(위 화살표)도 같은 자리.
- 확인: 320px 41개 카드에서 글자와 화살표 칸 겹침 0, 가로 넘침 없음. 375px·PC(1024px)에서 접힘/펼침 모두 정상.

## 23차 — 폰 화면 전체 재검토 (2026-11-27)
검사 방법: 화면 20개(홈, 검색 4종, 원문 3종, 표 3종, 업무 흐름 3종, 용어 2종, 시설정보 3종, 저장한 절)를
320·375·412px 폭, 글자 크기 보통·크게·아주 크게에서 자동 검사(가로 넘침, 잘림, 글자끼리·글자와 떠 있는 요소의 겹침,
작은 터치 영역, 맨 아래 내용이 떠 있는 막대에 가리는지)하고, 열린 상태(자동완성, ⋯ 메뉴, 차례, 이 절에서 찾기, 글자 크기)를 눈으로 확인.
768·1280px도 같은 검사로 회귀 확인.

고친 것
- 폰 머리줄 자동완성 목록이 검색칸 폭(글자 크기 단추 제외)에 갇혀 절 제목이 2~3줄로 꺾였다 → 화면 폭(좌우 12px)으로.
- 표 보기 화면(#/t/…)에서 넓은 표가 오른쪽이 잘린 채 안내가 없었다 → 원문 화면처럼 '표가 화면보다 넓습니다 — 옆으로 밀어 보세요 →'.
- '아주 크게'+320px에서 표 안 찾기 칸 때문에 화면이 1px 옆으로 밀렸다 → min-width:0.
- 좁은 폰·큰 글자에서 검색칸 안내 글이 글자 중간에서 잘렸다 → '…'로 끝나게.
- 시설 이름 검색('용천')에서 시설은 찾았는데 '본문에서 찾지 못했습니다' 큰 상자와 예시 칩이 바로 아래 떠 주의를 뺏었다 → 한 줄 안내로.
- 공유 링크 검색어의 앞뒤 빈칸이 제목에 그대로 보였다 → 떼고 보임.

확인만 한 것(문제 아님): 검색 결과 미리보기 두 줄 넘는 글(두 줄로 잘림), 원문 머리줄·저장 목록 제목(… 처리), 찾은 말 막대(떠 있는 막대).

## 24차 — 대시보드 전체 검토 (코드 검토 2갈래 + 화면 재검사)
새로 띄운 검토자 둘(JS 동작, CSS 겹침·일관성)에게 코드만 읽혀 찾은 것을 하나씩 화면에서 재현해 보고 고쳤다.

고친 것(동작)
- 시설 자료 파일을 받았는데 내용이 없으면(중간 서버가 HTML을 돌려줄 때) 시설 화면이 끝없이 다시 그려져 멈출 수 있었다 → 실패로 처리, 30초 안에는 다시 받지 않음('다시 시도'는 바로).
- 표 안에서 찾기가 첫 줄만 제목으로 보고 숨겨, 두 줄 제목·합친 칸이 있는 표(545개 중 약 150개)에서 칸이 엉뚱한 열 밑으로 밀렸다 → 제목 줄 수를 첫 줄 rowspan으로, 합친 칸 시작 줄도 같이 보임.
- 시설 링크(검색 자동완성 등)로 왔는데 그 시설이 목록 50개 밖이면 카드가 안 보였다 → 맨 앞으로 옮기고 그 카드로 내려가 초점.
- 용어·시설 카드로 바로 온 경우 초점은 맨 위 제목에 있어 Tab이 화면을 맨 위로 튀게 했다 → 그 카드에 초점.
- '#/fac?q=해포도'처럼 종류 없이 오면 늘 저수지로 열려 '없습니다'가 떴다 → 맞는 종류로.
- 사내망(http)에서 복사하면 초점이 맨 앞으로 사라졌다 → 누른 단추로 되돌림.
- 없는 절 주소에서 탭 제목이 앞 화면 그대로였다 → '절을 찾을 수 없습니다'.
- 자동완성을 Esc로 닫은 뒤 ↓로 다시 열리지 않았다 → 열림.
- 저장 알림이 없어진 '홈의 저장한 절'을 가리켰다 → 넓은 화면은 위 메뉴 '저장', 폰은 ⋯ 메뉴 '저장한 절'.

고친 것(화면)
- 머리줄 검색칸 초점 테가 연해서 거의 안 보였다 → 진한 청색 테.
- 방향키로 고른 자동완성 항목이 흰 바탕과 구분이 안 됐다 → 연청 바탕+왼쪽 청색 줄.
- 찾기 칸이 페이지 맨 아래 '이전·다음'을 가렸다 → 그만큼 아래 여백.
- '아주 크게'에서 하단 탭 이름이 두 줄이 되어 탭이 62→98px로 높아지며 찾은 말 막대와 겹쳤다 → 탭 이름은 한 줄 고정 크기.
- 폰 검색 범위 '절 번호·제목'이 '절 번'으로 잘렸다 → 보이는 이름 '제목', 칸 폭은 글자 크기에 맞춰.
- 알림이 찾은 말 막대 위에 겹쳤다 → 막대 위로.
- 아이폰 가로 화면의 둥근 모서리·노치에 원문 창 닫기 단추·맨 위로 단추가 들어갔다 → safe-area 여백(평소 값은 그대로).
- 옛 사파리에서 원문 창이 화면을 다 채우지 못할 수 있었다 → top/right/bottom/left 대체.
- 긴 한 낱말 제목이 결과 카드·자동완성을 밀 수 있었다 → 줄바꿈 허용(제목 낱말은 중간에서 꺾지 않고, 자리가 모자라면 편·쪽이 다음 줄로).
- 폰 작은 칩 36px → 40px.

그대로 둔 것: 용어 찾기에 글을 치면 첫 글자 칩이 풀리는 것(칩을 유지하면 'ㄱ'+'홍수'처럼 결과 0이 되기 쉬움), 쓰지 않는 옛 CSS 규칙 정리(화면에 영향 없음, 다음에 따로), 머리표(영문 작은 글씨) 13px.
검증: 20개 화면 × 320(보통·아주 크게)·1280px 자동 검사 문제 0, 시험 5/5, 검색 평가 그대로(1위 87%·5위 안 98%).

### 24차 3번째 검토(이번 고침의 부작용) — 고친 것
- 시설 카드를 연 채 '더 보기'를 누르면 화면이 그 카드로 튀어 올라갔다 → 같은 목록을 늘릴 때는 제자리.
- 첫 쪽 밖 시설을 맨 앞으로 옮긴 순서가 '더 보기' 뒤 원래대로 돌아가 카드가 자리를 옮겼다 → 늘 맨 앞.
- 시설 링크를 새로 열(자료를 처음 받을) 때는 카드 대신 제목에 초점이 갔다 → 카드에.
- 엇갈린 합친 칸이 있는 표에서 찾으면 한 줄이 여전히 옆 열로 밀렸다 → 아래 줄부터 올라가며 앵커를 이어서 보임(가상 표로 확인).
- 자동완성의 '동의어' 표가 가로로 늘어났다, 홈 예시 칩이 38px 그대로였다, PC 표 찾기 칸 폭이 바뀌었다 → 원래대로·40px.
